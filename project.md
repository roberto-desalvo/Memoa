# MVP – Funzionalità minime

Legenda: **[core]** = necessario per il primo rilascio · **[avanzata]** = rilasciabile in un secondo momento

---

## 1. Account e accesso

| Funzionalità | Descrizione | Priorità |
|---|---|---|
| Autenticazione e account utente | Registrazione, login e logout. Prerequisito della persistenza per utente. | [core] |
| Lingua dell'account | Scelta della lingua preferita (italiano o inglese) alla creazione dell'account, modificabile in seguito dalle impostazioni. Si applica a interfaccia e riassunti, e fa da ripiego per la trascrizione quando il riconoscimento automatico è incerto. | [core] |

## 2. Gestione contenuti in ingresso

| Funzionalità | Descrizione | Priorità |
|---|---|---|
| Registrazione audio | Registrazione diretta dall'interfaccia. | [core] |
| Upload audio | Caricamento di file audio. | [core] |
| Scrittura testo | Inserimento diretto di testo dall'interfaccia. | [core] |
| Upload testo | Caricamento di file di testo. | [core] |
| Conservazione dell'originale | Il file audio (o l'immagine) resta collegato al testo estratto, per poterlo riascoltare o rivedere. Per l'audio si conserva solo la copia normalizzata in Opus, non il file caricato o registrato. | [core] |
| Testo da immagine | Upload di immagine con scrittura a mano ed estrazione del testo (OCR / HTR). | [avanzata] |
| Upload video | Caricamento di file video, con estrazione e trascrizione della sola traccia audio. | [avanzata] |

## 3. Elaborazione dei record

| Funzionalità | Descrizione | Priorità |
|---|---|---|
| Trascrizione | Conversione in testo delle registrazioni audio. | [core] |
| Riconoscimento automatico della lingua | Per ogni registrazione la lingua (italiano o inglese) viene rilevata in automatico; se il rilevamento è incerto si usa la lingua dell'account. | [core] |
| Stato di elaborazione | Trascrizione e indicizzazione sono asincrone: l'utente vede se un record è "in elaborazione", "pronto" o "in errore", e può riprovare in caso di errore. | [core] |

## 4. Gestione e consultazione dei record

| Funzionalità | Descrizione | Priorità |
|---|---|---|
| Persistenza e recupero | Salvataggio e recupero dei record per utente. | [core] |
| Vista elenco | Lista cronologica con data, tipo di origine (audio / testo / immagine) e anteprima. | [core] |
| Modifica ed eliminazione | Modifica e cancellazione dei record, inclusa la correzione delle trascrizioni. | [core] |
| Ricerca semantica | Ricerca per significato sui record, anche tra lingue diverse (es. query in inglese su note in italiano), tramite un modello di embedding multilingue. | [core] |
| Domande sui propri record (Q&A / RAG) | Risposta in linguaggio naturale con rimando ai record di origine. | [avanzata] |
| Riassunti periodici | Generazione periodica di riassunti dei record. | [avanzata] |
| Categorie | Organizzazione dei record in categorie. | [avanzata] |
| Tag liberi | Etichette libere in aggiunta alle categorie. | [avanzata] |

## 5. Privacy e dati personali

| Funzionalità | Descrizione | Priorità |
|---|---|---|
| Informativa privacy | Informativa conforme al GDPR. | [core] |
| Esportazione dati | Esportazione dei propri record. | [core] |
| Eliminazione account | Cancellazione dell'account e di tutti i dati associati. | [core] |

## 6. Scelte tecniche

Contesto: al massimo 10 utenti nella fase iniziale, budget di manutenzione massimo di circa 10 € al mese.

| Scelta | Opzioni principali | Impatto | Decisione |
|---|---|---|---|
| App mobile | PWA (web installabile) · app cross-platform (React Native, Flutter) · app nativa | Pubblicare sugli store ha un costo annuale (Apple in particolare) che pesa sul budget; una PWA lo evita. Limiti della PWA: la registrazione si interrompe con schermo bloccato o app in background; su iOS l'installazione è manuale ("Aggiungi alla schermata Home") e le notifiche push funzionano solo con l'app installata. In futuro è possibile impacchettarla per gli store (es. Trusted Web Activity su Android) | **PWA** |
| Framework frontend | Angular · React · Vue · Svelte · Blazor WebAssembly | Angular offre un pacchetto ufficiale per la PWA e una struttura vicina a quella di .NET. Best practice e scelte architetturali della PWA da definire in seguito | **Angular (TypeScript)** |
| Architettura backend | Backend-as-a-Service (es. Supabase, Firebase) · server proprio su VPS economico · funzioni serverless | Free grant mensile del piano Flex Consumption: 250.000 esecuzioni e 100.000 GB-s per sottoscrizione. Lo storage account obbligatorio è fatturato a parte (pochi centesimi a questi volumi). Senza istanze "always ready" ci sono cold start. Esclude l'esecuzione di modelli pesanti (es. Whisper) dentro le funzioni | **C# .NET su Azure Functions, piano Flex Consumption** |
| Database e ricerca vettoriale | Azure SQL Database (offerta gratuita, tipo VECTOR e indici vettoriali) · Azure Cosmos DB for NoSQL (free tier, ricerca vettoriale integrata) · Postgres con pgvector esterno ad Azure | Entrambe le opzioni Azure hanno un'offerta gratuita permanente e tengono record ed embedding nello stesso database. Offerta gratuita Azure SQL: fino a 10 database per sottoscrizione, ciascuno con 100.000 vCore-secondi al mese e 32 GB; tutti i database gratuiti stanno nella stessa regione, fissata dal primo. Ricerca semantica nell'MVP con ricerca esatta (VECTOR_DISTANCE), adeguata a questi volumi; l'indice vettoriale DiskANN è un'ottimizzazione successiva, richiede almeno 100 righe con vettori e la sua disponibilità in West Europe va verificata con un test sul database | **Azure SQL Database (offerta gratuita, serverless)** |
| Autenticazione | Microsoft Entra External ID · servizio di auth dedicato · implementazione propria | Va usato un tenant esterno (External ID), non il tenant aziendale di Entra ID. Gratuito fino a 50.000 utenti attivi al mese; i componenti aggiuntivi premium (es. autenticazione via SMS) sono a pagamento. Gestisce registrazione, conferma email e reset password | **Microsoft Entra External ID** |
| Storage dei file | Azure Blob Storage · object storage esterno (es. Cloudflare R2) | Nessun piano gratuito permanente (5 GB solo per i primi 12 mesi dell'account gratuito), ma il costo è trascurabile: tier Hot LRS circa 0,018-0,02 $/GB al mese, circa il doppio con la ridondanza GRS scelta per il backup. Storage account dedicato ai dati utente (blob e coda), separato da quello di sistema delle Functions: non costa nulla in più e isola chiavi di accesso, regole di ciclo di vita e cancellazioni GDPR. Audio compresso (Opus, circa 0,25 MB al minuto) e immagini ridimensionate lato client. Regola di ciclo di vita per spostare i file vecchi nel tier Cool | **Azure Blob Storage, storage account dedicato ai dati** |
| Trascrizione | Whisper self-hosted su Azure Container Apps Jobs · API cloud (Mistral Voxtral, Groq, OpenAI, Azure AI Speech) | Il job viene avviato dai messaggi in coda ed è fatturato solo durante l'esecuzione, dentro il grant mensile gratuito di Container Apps (180.000 vCPU-s e 360.000 GiB-s per sottoscrizione). Velocità e qualità sull'italiano su CPU sono da misurare (modello di partenza: large-v3-turbo, con la quantizzazione offerta dalla libreria .NET scelta, es. formato GGML per Whisper.net). Con il worker in .NET, faster-whisper (solo Python) è escluso. Il riconoscimento della lingua è integrato. Il servizio va implementato dietro un'interfaccia sostituibile: alternativa principale Mistral Voxtral (endpoint UE; limiti attuali dell'API: 60 minuti e 500 MB per file, formati WAV, MP3, FLAC, OGG, WEBM), ma da agosto 2026 i termini di Mistral limitano l'accesso API ai clienti business: verificare l'applicabilità a un progetto personale in UE | **Whisper self-hosted su Container Apps Jobs, worker in C# .NET (libreria di inferenza da definire), sostituibile con API; pesi del modello inclusi nell'immagine del container (spostabili in seguito su storage esterno)** |
| Modello di embedding | Azure OpenAI text-embedding-3-small · OpenAI diretto · Mistral Embed · modello locale nella Function (es. multilingual-e5-small via ONNX Runtime) · modello in container | Anche la query di ricerca va trasformata in vettore in tempo reale, quindi gli embedding vengono calcolati dalla Function (non dal job): subito per i record di testo, dopo la trascrizione per gli audio. Costo stimato: pochi centesimi al mese (0,02 $ per milione di token). 1.536 dimensioni, compatibili con il tipo VECTOR di Azure SQL (max 1.998 in float32). Deployment "Data Zone Standard (EU)" in West Europe, così l'elaborazione resta in UE; evitare "Global Standard". Salvare accanto a ogni vettore il nome del modello, perché cambiarlo richiede di ricalcolare tutti i vettori | **Azure OpenAI text-embedding-3-small (Data Zone Standard EU)** |
| Elaborazione asincrona | Coda di job · funzioni attivate da eventi · polling semplice · orchestrazione con Durable Functions | Flusso: il client carica il file direttamente su Blob Storage con un token SAS fornito dalla Function, poi la Function scrive sulla coda di trascrizione l'URL del blob; il Container Apps Job esegue la trascrizione, la salva nel database e scrive un messaggio su una seconda coda di indicizzazione; una Function attivata da questa coda calcola l'embedding e porta il record a "pronto". I record di testo vengono salvati nel database dalla Function HTTP e, parallelamente, scritti sulla coda di indicizzazione, così l'indicizzazione segue lo stesso percorso per tutti i record. Alternative scartate per la notifica di fine trascrizione: chiamata HTTP dal job alla Function, timer che interroga il database (terrebbe sveglio il database serverless consumando i vCore-secondi gratuiti), embedding calcolato nel job. Le code stanno nello storage account dedicato ai dati utente, insieme ai blob; costo trascurabile (poche transazioni). Service Bus non è necessario a questi volumi. Retry tramite i meccanismi della coda. Durable Functions valutato e scartato per costo (vedi riga "Orchestrazione dell'elaborazione") | **Azure Storage Queue: coda di trascrizione (Function → job) e coda di indicizzazione (job → Function per gli audio; Function HTTP → Function per i record di testo)** |
| Aggiornamento dello stato nel frontend | Polling dal client · Azure SignalR Service / Web PubSub (piano Free) · notifiche Web Push della PWA | Polling: finché ci sono record "in elaborazione" e l'app è visibile, il client interroga periodicamente lo stato; nessuna risorsa aggiuntiva; ritardo pari all'intervallo; funziona solo con l'app aperta. Costo stimato: con 900 record al mese e circa 36 chiamate per record (ogni 5 secondi per 3 minuti) circa 32.000 esecuzioni, dentro il grant di Flex Consumption. SignalR / Web PubSub Free: 20 connessioni contemporanee e 20.000 messaggi al giorno, nessuno SLA; Standard fuori budget. Web Push: avvisa anche ad app chiusa, nessun costo Azure, su iOS solo con app installata; la notifica passa dai server dei fornitori dei browser (contenuto cifrato, inviare solo identificativi). Web Push combinabile con il polling in futuro | **Polling dal client (Web Push da valutare in seguito)** |
| Orchestrazione dell'elaborazione | Code e funzioni separate · Durable Functions con backend Azure Storage · Durable Functions con Durable Task Scheduler · Durable Functions con backend SQL (MSSQL) | Durable Functions coordina i passaggi per ogni record (avvio del Container Apps Job, attesa della fine trascrizione con timeout, calcolo dell'embedding, aggiornamento dello stato); la trascrizione resta nel job. Retry con attesa crescente e timeout gestiti dall'orchestrazione. Le esecuzioni di orchestratore e attività rientrano nel grant gratuito di Flex Consumption e l'attesa non è fatturata. SKU Consumption del Durable Task Scheduler (stabile da aprile 2026): pagamento per azione (avvio di un'orchestrazione, avvio e risultato di un'attività, timer, evento esterno), nessun costo fisso; circa 10 azioni per record, quindi poche decine di migliaia di azioni al mese a questi volumi; fino a 500 azioni al secondo; cronologia conservata fino a 30 giorni, con eliminazione automatica configurabile (autopurge); fino a 10 scheduler per regione e sottoscrizione e 5 task hub per scheduler. Prezzi in West Europe dal listino ufficiale (API Azure Retail Prices, ottobre 2026): SKU Consumption 0,00429 $ per azione (unità di misura "1"), cioè circa 0,04 $ per record con 10 azioni; SKU Dedicated 0,979 $ all'ora per capacity unit (circa 715 $ al mese), fuori budget. Discrepanza da chiarire: la documentazione attuale calcola la spesa "per milione di azioni", mentre il listino e un esempio della documentazione in anteprima (0,003 $ per azione) indicano un prezzo per singola azione; nel secondo caso il costo supera il budget già con poche centinaia di record al mese. Il listino ha una voce per West Europe; disponibilità da confermare all'avvio (elenco regioni via Azure CLI). Autenticazione con Entra ID e RBAC (identità gestite); emulatore locale per lo sviluppo. GDPR: la cronologia delle orchestrazioni conserva input e output, quindi nelle orchestrazioni vanno passati solo identificativi, mai testi o trascrizioni | **Nessuna orchestrazione: code e funzioni separate. Durable Task Scheduler scartato perché, con il prezzo per azione del listino, supera il budget già con poche centinaia di record al mese** |
| Registry delle immagini container | Azure Container Registry · GitHub Container Registry · Docker Hub | Azure Container Registry Basic costa circa 5 $ al mese, metà del budget. GHCR e Docker Hub sono gratuiti a questi volumi e utilizzabili da Container Apps. GHCR: storage e banda del Container registry attualmente gratuiti (GitHub avvisa almeno un mese prima di eventuali cambi), nessun limite di pull pubblicato, push dalle GitHub Actions con il GITHUB_TOKEN senza segreti aggiuntivi. Nessun registry diverso da ACR supporta le identità gestite: Container Apps va configurato con il registry anche per immagini pubbliche, e per un'immagine privata serve un personal access token con scope read:packages | **GitHub Container Registry (GHCR), immagine privata (rendibile pubblica in seguito)** |
| Formato di registrazione | A) Formato nativo del browser con preferenza Opus/WebM e fallback MP4/AAC · B) Come A, più copia normalizzata creata nel job con ffmpeg (Opus mono a basso bitrate) · C) Codifica uniforme nel browser con un encoder WebAssembly | Da Safari 18.4 (iOS 18.4, marzo 2025) tutti i browser principali registrano Opus in WebM; il fallback MP4/AAC serve solo per iOS più vecchi. I file registrati dal browser non sono navigabili (seek) e hanno bitrate diversi tra browser: B risolve entrambi i problemi con un passaggio in più nel job, e richiede di decidere se conservare l'originale o solo la copia normalizzata. C dà un formato uniforme fin dall'origine ma aggiunge codice, dipendenze e consumo di batteria. In ogni caso: scelta del formato con MediaRecorder.isTypeSupported(), Blob creato con il tipo effettivamente scelto, nessun bitrate personalizzato. Riproduzione su Safari da verificare in fase di test | **B) Formato nativo del browser (preferenza Opus/WebM, fallback MP4/AAC), normalizzato nel job con ffmpeg in Opus; si conserva solo la copia normalizzata** |
| Hosting del frontend | Azure Static Web Apps Free · Cloudflare Pages · Netlify · Vercel Hobby · Blob Storage come sito statico | Piano Free di Static Web Apps: 100 GB di banda al mese, 2 domini personalizzati, 250 MB per ambiente, nessuno SLA. Non include il collegamento delle proprie Functions né l'autenticazione personalizzata (solo piano Standard): il frontend gestisce quindi il login con Entra External ID tramite MSAL e chiama direttamente le Functions con il token (CORS abilitato sulle Functions). Se l'uso diventa commerciale, valutare la migrazione (es. Cloudflare Pages, che permette l'uso commerciale e ha banda illimitata) | **Azure Static Web Apps (piano Free), con eventuale migrazione in caso di uso commerciale** |
| Regione dei dati | Data center UE · altre regioni | Rilevante per il GDPR. Tutte le risorse Azure (Functions, Azure SQL, storage, Container Apps) vanno create nella stessa regione, per latenza e per evitare costi di traffico tra regioni; la regione dei database SQL gratuiti è già fissata da quello esistente. Da verificare in questa regione la disponibilità del piano Flex Consumption e degli indici vettoriali di Azure SQL. Tenant Entra External ID con residenza dati in Europa | **West Europe (Paesi Bassi)** |
| Dominio ed email | Dominio proprio · sottodominio gratuito del servizio di hosting | Il dominio ha un piccolo costo annuale. Le email di registrazione e reset password sono inviate da Entra External ID, quindi non serve un servizio email proprio. Dominio personalizzato da rivalutare più avanti | **Dominio gratuito di Azure Static Web Apps** |
| Backup | Database: backup automatici di Azure SQL · export periodico esterno (.bacpac). File: soft delete + versioning · copie nel tier Archive · replica in un secondo storage account · ridondanza geografica (GRS) | Testi, trascrizioni ed embedding stanno nel database; in Blob Storage ci sono solo audio e immagini. L'offerta gratuita di Azure SQL include 32 GB di spazio per i backup. File: soft delete e versioning proteggono da cancellazioni e sovrascritture accidentali; la GRS replica in modo asincrono nella regione abbinata (North Europe, Irlanda, quindi in UE) e protegge da guasti dell'intera regione, ma replica anche le cancellazioni; il blocco CanNotDelete impedisce l'eliminazione accidentale dello storage account. I file cancellati restano recuperabili per 14 giorni: da indicare nell'informativa privacy. Le versioni precedenti dei file vengono eliminate dopo 30 giorni tramite una regola di lifecycle management dello storage account (configurazione, non codice); con il soft delete attivo restano poi recuperabili per altri 14 giorni | **Database: backup automatici di Azure SQL (export esterno da valutare in seguito). File: soft delete e versioning con conservazione di 14 giorni, ridondanza GRS, blocco CanNotDelete sullo storage account, eliminazione delle versioni precedenti dopo 30 giorni** |
| Controllo dei costi | Budget di Azure Cost Management con avvisi · avvisi più azioni automatiche (action group) | I budget inviano solo notifiche e non fermano le risorse; per reagire in automatico va collegato un action group (es. una Function che disattiva servizi). Possibili avvisi sia sulla spesa effettiva sia su quella prevista a fine mese | **Budget mensile di 10 €, avvisi al 50%, 80% e 100% della spesa effettiva più un avviso sulla spesa prevista a fine mese; action group automatico opzionale** |
| Monitoraggio e log | OpenTelemetry + Application Insights · solo log della piattaforma | Application Insights basato su workspace usa le tariffe di Log Analytics: primi 5 GB al mese gratuiti, poi circa 2,30 $/GB; conservazione gratuita per 31 giorni. Limite giornaliero di ingestione tarato sui 5 GB gratuiti mensili (circa 160 MB al giorno): superato il limite, i log del resto della giornata vanno persi. Conservazione entro i 31 giorni gratuiti. Workspace in West Europe. GDPR: mai registrare contenuti dei record, trascrizioni, email o token; usare solo identificativi; verificare cosa raccolgono in automatico le strumentazioni (testo delle query SQL, URL, indirizzi IP); requisito da comunicare al coding agent | **OpenTelemetry + Application Insights, con limite giornaliero e conservazione entro le soglie gratuite; nessun dato sensibile nei log** |
| Gestione dei segreti e identità | Azure Key Vault · impostazioni delle app · identità gestite | Key Vault Standard non ha costo fisso, si pagano solo le operazioni. Con le identità gestite molti servizi (Azure SQL, Storage, Azure OpenAI) si raggiungono senza segreti; in Key Vault restano solo le credenziali non sostituibili (es. token del registry se l'immagine è privata). Ripartizione tra identità assegnate dall'utente e dal sistema da definire più avanti. Key Vault ospiterà probabilmente anche le chiavi di cifratura dei dati a riposo (da discutere) | **Azure Key Vault per i segreti; identità gestite (user-assigned e system-assigned) per la comunicazione tra servizi** |
| Deploy automatico | GitHub Actions · Azure DevOps Pipelines · deploy manuale | Pipeline separate per frontend (Static Web Apps), Functions e immagine del container | **GitHub Actions** |
| Infrastruttura come codice | Bicep · Terraform · OpenTofu · Pulumi · Azure Developer CLI (azd, orchestratore sopra Bicep o Terraform) | Tutte le opzioni sono gratuite o quasi a questi volumi. Le impostazioni del repository GitHub non sono gestibili con Bicep | **Bicep per tutto ciò che supporta; file di istruzioni manuali per ciò che resta fuori (es. tenant e flussi utente di Entra External ID, impostazioni GitHub)** |

Con la stessa sottoscrizione i grant gratuiti di Functions e Container Apps sono condivisi tra dev e prod; ogni ambiente usa uno dei 10 database SQL gratuiti, ciascuno con la propria quota. Il budget e i suoi avvisi coprono entrambi gli ambienti | **Due ambienti, dev e prod, nella stessa sottoscrizione** |

## 7. Vincoli da definire

| Vincolo | Valore |
|---|---|
| Formati accettati (audio) | MP3, M4A/AAC, WAV, FLAC, Ogg/Opus, WebM, AMR/3GP, verificati sul formato reale del file con ffprobe (non sull'estensione); normalizzazione nel job in Opus; nessun file video |
| Formati accettati (testo) | Tutti i formati di testo, inclusi DOCX e PDF |
| Formati accettati (immagine) | Da definire |
| Dimensione massima dei file | Audio: 350 MB per il file caricato (prima della normalizzazione). Testo: 10 MB per il file caricato, più un limite di 50.000 caratteri sul testo estratto. Immagine: da definire |
| Durata massima delle registrazioni | 30 minuti |
| Lingue supportate al lancio | Italiano, inglese |
| Piattaforme target | Web, mobile |
